# Настройка Platega

Официальная документация: https://docs.platega.io/ . API: https://app.platega.io/ . Сведения проверены 03.10.2026.

1. В кабинете Platega получите Merchant ID и API Secret. Сохраните их только в `.env`: `PLATEGA_MERCHANT_ID`, `PLATEGA_SECRET`.
2. Приложение отправляет JSON по HTTPS с заголовками `X-MerchantId` и `X-Secret`. Страница выбора способов оплаты создаётся запросом `POST /v2/transaction/process`: `paymentDetails` (сумма, RUB), описание, адреса возврата, payload и `metadata.userId`. Доступные способы определяются настройками вашей кассы.
3. В настройках Callback URLs укажите `https://<DOMAIN>/platega`. Требуется действительный сертификат доверенного центра. Этот endpoint одинаков для polling и webhook режима Telegram.
4. Callback содержит `id`, `amount`, `currency`, `status`, `paymentMethod`. Для зачисления требуется `CONFIRMED`; отмена — `CANCELED`, возврат — `CHARGEBACKED`. Приложение проверяет заголовки, сверяет статус через `GET /transaction/{id}` и сопоставляет сумму и валюту с локальным заказом. Возврат пользователя на сайт сам по себе не подтверждает платеж.
5. Повтор callback не должен повторно выдавать дни и устройства. При сбое панели примените повторную синхронизацию уже зачисленной подписки. При временном отказе API callback возвращает ошибку для повторной доставки; планировщик сверяет ожидающие платежи.
6. Проверьте реальный тестовый платёж в согласованном с Platega режиме: создание ссылки, успешную оплату, уведомление, подписку, повтор callback и возврат. Секреты и полные платежные ответы в документацию не записывайте.
7. В боте откройте `/documents`, получите полный текст политики и соглашения, включая все части и файлы для сохранения. Проверьте `/privacy`, `/terms`, `/support`, `/tariffs` на сайте. В боте пройдите путь «Тарифы → Оплатить → состав заказа → Оплатить с итоговой суммой»: цена на кнопке должна совпадать с суммой заказа после скидок и выбора устройств. Чтение документов перед покупкой должно сохранять промокод и параметры заказа. На время согласования оставьте `PLATEGA_REVIEW_MODE=True`; после регистрации выключите и обновите сервисы.

Platega используется как основная касса. По умолчанию подписки продлеваются отдельными платежами по выбору пользователя; дополнительно доступно автопродление (ниже).

## Автопродление (рекуррентные СБП-подписки)

Включается флагом `PLATEGA_RECURRING_ENABLED=True` в `.env` (по умолчанию выключен, кнопки автопродления не показываются). **Перед включением Platega должна подключить кассе метод «Подписка»**: пока он не включён, `POST /transaction/process` с `paymentMethod: 6` отвечает `400 Wrong input parameters (paymentMethod: Subscription)`. Проверено 08.10.2026 на боевой кассе — метод ещё не подключён.

Как это работает:

1. Пользователь выбирает тариф (и число устройств) и жмёт «🔁 С автопродлением» в боте либо ставит галочку «Автопродление» на сайте или в Mini App. Промокод с автопродлением не сочетается, цена должна быть целой (API подписок не принимает копейки), срок тарифа должен ложиться на интервал Platega (день ×1–31, неделя ×1–4, месяц = 30 дней ×1–12, год ×1–3): 30, 90, 180, 365 дней подходят.
2. Приложение создаёт подписку (`POST /transaction/process`, `paymentMethod: 6`; `transactionId` в ответе — это ID подписки) и записывает её в `recurring_subscriptions` до выдачи ссылки. Человек привязывает счёт в банке на странице Platega за 30 минут.
3. Каждое списание приходит callback'ом на тот же `/platega` (`SubscriptionId` + `NextChargeAt`, ключи с заглавной буквы). Обработчик проверяет секрет, сверяет подписку через `GET /subscription/{id}` (сумма), по возможности само списание через `GET /transaction/{id}` и проводит его как обычный платёж: строка `payments` с `source='auto'`, `provider_payment_id` = ID списания. Дни, слоты, реферальный бонус и возвраты работают без отдельной ветки; повтор callback ничего не добавляет.
4. Callback о статусе подписки (`SUBSCRIPTION_*`) Platega может прислать без заголовков, поэтому телу не доверяем: реальный статус берётся из `GET /subscription/{id}`.
5. Списание не прошло (`CANCELED`) — Platega повторов не делает, подписка уходит в `past_due`, пользователю приходит уведомление с кнопкой продления.
6. Отключение: бот (🔁 Автопродление), кабинет, Mini App (`POST /payment/autorenew/cancel` → `POST /subscription/{id}/cancel`) или ссылка из письма Platega. Отмена окончательна.
7. Сумма подписки фиксируется при создании. Поэтому докупка устройств посреди периода **отключает** автопродление (иначе следующее списание сбросило бы слоты) — пользователь получает уведомление и может подключить его заново.
8. Джоб `reconcile_recurring` (каждые 10 минут) закрывает брошенные привязки (>35 мин), подтягивает внешние отмены и раз в 6 часов сверяет число списаний в Platega с зачисленными: расхождение пишется в ERROR («Платега списала N раз, у нас зачислено M») — нужна ручная сверка в кабинете.
9. Напоминания «продлите» (нудж за 7 дней, D-3/D-1/D0) пользователям с активным автопродлением не шлются.

Деплой: `python3 fix_db.py` создаёт таблицу `recurring_subscriptions` и пересоздаёт индекс `uq_payment_user_pending` (автосписания не конкурируют с ручным счётом). Проверка после включения метода в Platega: создать подписку на минимальный тариф, привязать счёт, убедиться, что приходит callback списания, дни добавляются один раз, а «Отключить» останавливает списания. **Неизвестно из документации:** списывает ли Platega первый платёж сразу при привязке — проверьте на первой реальной подписке; дни выдаются только по CONFIRMED-callback списания.


Политика и соглашение доступны пользователю постоянно. Личные обращения об оплате и возвратах принимаются через встроенную поддержку. Тарифы и параметры услуги отображаются до перехода к кассе. Публикации в Telegram-канале редактируются отдельно его администратором.

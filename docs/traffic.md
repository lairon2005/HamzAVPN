# Докупка трафика

Пользователь с активной оплаченной подпиской может докупить пакеты трафика из профиля бота, личного кабинета и главного экрана Mini App. На пробном периоде, после истечения подписки и на безлимитном тарифе докупка недоступна. Это прибавка к ежемесячной квоте до конца текущей подписки; расход не сбрасывается, дата окончания не меняется.

## Настройка

В админ-панели бота откройте «Трафик»: задайте размер пакета, месячную цену и максимальное число пакетов. Значения хранятся в `app_settings`: `traffic_pack_gb`, `traffic_pack_price`, `max_traffic_packs`. Исходные значения перенесены из реализации flaskVPN; новые суммы рассчитываются по текущим настройкам на сервере. Максимум `0` отключает продажу новых пакетов. Уже оплаченный объём не урезается при изменении настроек.

Базовая квота берётся из активного каталога тарифов HamzAVPN; `NULL` и `0` сохраняют значение «безлимит». Для старых подписок без сохранённой квоты значение читается из Remnawave при первом расчёте докупки.

Стоимость отдельной докупки: месячная цена пакета × оставшиеся дни / 30, округление вверх до рубля, минимум месячная цена за каждый пакет. При покупке/продлении тарифа: цена пакета × число расчётных месяцев тарифа × число пакетов. Скидка по промокоду действует только на тариф. В чекауте уже купленные пакеты выбраны по умолчанию; пользователь может изменить их количество.

## Платежи и восстановление

Докупка проводится через Platega как `Payment.kind='traffic'` без `tariff_id`. Объём записывается в `extra_traffic_gb` до обращения к шлюзу, поэтому потеря ответа API не теряет состав заказа. Callback проверяет авторизацию, сумму, валюту и статус через API. Статус платежа и начисление ГБ коммитятся одной транзакцией под блокировками платежа и пользователя; повтор не добавляет трафик.

В Remnawave записывается абсолютный лимит «квота + оплаченные ГБ». Сбой панели оставляет `sync_pending`; сверка повторяет выдачу без второго начисления. Возврат отдельной докупки один раз вычитает её объём, сохраняя срок и устройства. Возврат пакета из уже заменённого продлением периода не уменьшает новый оплаченный объём. Подтверждённая позднее оплата локально отменённого счёта зачисляется; после окончания подписки пакеты не активируют её заново.

Фиксированная сумма Platega-подписки включает пакеты, выбранные при её создании. После изменения дополнительных услуг прежнее автопродление отключается; подключите его заново с новым составом. Неудачная отмена повторяется при сверке платежа. Stars не продлевают подписку с оплаченными дополнительными услугами.

Раз в час сверка обнуляет докупленные ГБ истёкших подписок и синхронизирует панель. Бот предупреждает об использовании 90% и 100% месячной квоты, не чаще одного сообщения каждого уровня за месяц.

## Обновление и проверка

1. Сделайте резервную копию БД вне репозитория.
2. Выполните `./refresh.sh`: `fix_db.py` идемпотентно добавляет `extra_traffic_gb` в `users`, `payments`, `recurring_subscriptions`.
3. Проверьте доступность `/payment/traffic/quote` и `/payment/traffic`: без авторизации оба маршрута должны возвращать 401.
4. Проверьте профиль бота, сайт и Mini App на тестовой активной подписке; расчёт и кнопка оплаты должны совпадать. Проверку реальной оплаты выполняйте отдельным согласованным тестовым платежом.
5. Запустите `python3 -m pytest -q`, компиляцию Python, синтаксическую проверку JS и рендер изменённых шаблонов.

Для проверки транзакционных блокировок используйте отдельную тестовую PostgreSQL и задайте `PAYMENT_TEST_DSN`. Тесты платежей создают собственную временную схему и удаляют её по завершении; внешние API подменены.

# Проверка ошибок Platega

Проверка статуса разового платежа использует `GET /transaction/{id}`. Ошибка
запроса не подтверждает оплату или отмену: выдача услуги разрешается только
после проверки идентификатора, статуса `CONFIRMED`, суммы и валюты заказа.

В сообщении «Сверка платежа … отложена» указаны безопасная причина и HTTP-статус:

- `timeout` — истекло время ожидания; `network` — ошибка соединения.
- HTTP 401/403 — проверить доступ кассы и настройки API в `.env`.
- HTTP 404 — проверить принадлежность идентификатора кассе. ID рекуррентной
  подписки проверяется через `/subscription/{id}`, а не как разовый платеж.
- HTTP 429 — ограничение частоты; HTTP 5xx — отказ шлюза.
- `invalid_response` — некорректный JSON или несоответствие формата платежа.

Тело ответа, заголовки авторизации и секреты не выводятся в лог. Для GET при
сетевом отказе, HTTP 408, 429 или 5xx разрешён один короткий повтор. Короткий
`Retry-After` учитывается; при значении больше двух секунд немедленного повтора
нет. Создание платежа через POST автоматически не повторяется.

После отказа обновляется время попытки проверки, чтобы остальные платежи
получали очередь. `last_checked_at` обозначает попытку и сам по себе не
подтверждает успешную сверку. При общем отказе шлюза текущий проход прерывается;
следующая плановая сверка выполняется через пять минут. Финансовый статус заказа
при этом сохраняется. HTTP 404 не останавливает сверку остальных заказов.

Сначала сопоставьте время сообщения со следующим проходом планировщика и
проверьте состояние заказа и API. Не меняйте статус вручную только из-за
timeout, 404 или 5xx. Не публикуйте полные ответы платежной системы, `.env` или
персональные данные при обращении в поддержку.

## Подключение автопродления

Platega документирует [рекуррентные СБП-подписки](https://docs.platega.io/создать-подписку-40029698e0).
По ответу менеджера от 08.10.2026 требуется отдельное согласование и подтверждение
«трафика 5к в день в течение 3–4 недель». Единицы и критерий подтверждения нужно
уточнить у Platega: из этой формулировки нельзя достоверно определить, идёт ли
речь о рублёвом обороте. До согласования автопродление должно оставаться
выключенным; разовые платежи доступны по обычному сценарию.
